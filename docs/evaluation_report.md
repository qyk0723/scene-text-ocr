# ICDAR2015 评估报告

> 生成日期：2026-09-25
> 模型：PaddleOCR PP-OCRv6（medium det + medium rec），预训练权重，未微调
> 推理设备：CPU（PaddlePaddle 3.3.1）

## 一、数据集

| 任务 | 数据 | 规模 |
| --- | --- | --- |
| 检测 | ICDAR2015 detection/test | 500 张整图 + 500 个标注文件 |
| 识别 | ICDAR2015 recognition/test | 2074 张单行裁剪图 + test.txt |

## 二、检测结果

| 指标 | 数值 |
| --- | --- |
| 精确率 | 61.86% |
| 召回率 | 26.23% |
| F1 | 36.84% |
| GT 框数 | 5230 |
| 预测框数 | 2218 |
| 匹配框数 | 1372 |
| 平均耗时 | 27.13 s/张（CPU） |

匹配策略：IoU 阈值 0.5，贪心一对一匹配。

## 三、识别结果

| 指标 | 数值 |
| --- | --- |
| 字符准确率 | 82.89% |
| 行级完全匹配率 | 71.50% |
| 平均耗时 | 1.757 s/张（CPU） |

计算方法：字符准确率按编辑距离（`1 - 编辑距离 / max(len)`）逐行取平均；行级匹配率为预测与标注完全相等比例；忽略大小写（ICDAR2015 标准）。

## 四、评测方法

- 检测：对整图运行 PP-OCRv6 检测 + 识别，取检测框（`dt_polys`）与 GT 四边形框对比，IoU ≥ 0.5 记为匹配。
- 识别：对单行裁剪图运行完整 OCR，取识别文本与 GT 文字比对。
- 指标均为全局聚合（累计匹配数 / 累计总数）。

## 五、已知局限

**检测召回率偏低（26.23%）的主要原因是标注粒度错配**：ICDAR2015 检测标注为**词级**框（每个单词一个框），而 PP-OCR 检测输出为**文本行级**框（一行文字合并为一个框）。一个大行框与多个小词框在 IoU 0.5 下难以匹配，结构性压低召回率。实验已排除检测阈值因素（将框阈值从默认降至 0.4，召回率仅提升约 1.7%）。

此外，本镜像的检测标注文字被剥离为统一的 `###` 占位符，无法区分有效文本区与「无效区」（do-not-care），全部按有效 GT 计入，进一步影响指标口径。

该局限将在论文中作为「预训练模型行级输出 vs 词级标注」的说明项。
