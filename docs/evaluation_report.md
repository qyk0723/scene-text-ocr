# ICDAR2015 评估报告

> 生成日期：2026-09-25（消融与模型对比实验更新于 2026-09-26）
> 模型：PaddleOCR PP-OCRv6（medium det + medium rec），预训练权重，未微调
> 推理设备：CPU（PaddlePaddle 3.3.1）
> 测试环境：Windows 11，Intel Core i5-1340P，python 3.11（conda 环境 scene-text）

## 一、数据集

| 任务 | 数据 | 规模 |
| --- | --- | --- |
| 检测 | ICDAR2015 detection/test | 500 张整图 + 500 个标注文件 |
| 识别 | ICDAR2015 recognition/test | 2074 张单行裁剪图 + test.txt |

## 二、检测结果

| 指标 | 数值 |
| --- | --- |
| 精确率 | 61.86% |
| 召回率 | 26.23% |
| F1 | 36.84% |
| GT 框数 | 5230 |
| 预测框数 | 2218 |
| 匹配框数 | 1372 |
| 平均耗时 | 27.13 s/张（CPU） |

匹配策略：IoU 阈值 0.5，贪心一对一匹配。

## 三、识别结果

| 指标 | 数值 |
| --- | --- |
| 字符准确率 | 82.89% |
| 行级完全匹配率 | 71.50% |
| 平均耗时 | 1.757 s/张（CPU） |

计算方法：字符准确率按编辑距离（`1 - 编辑距离 / max(len)`）逐行取平均；行级匹配率为预测与标注完全相等比例；忽略大小写（ICDAR2015 标准）。

## 四、评测方法

- 检测：对整图运行 PP-OCRv6 检测 + 识别，取检测框（`dt_polys`）与 GT 四边形框对比，IoU ≥ 0.5 记为匹配。
- 识别：对单行裁剪图运行完整 OCR，取识别文本与 GT 文字比对。
- 指标均为全局聚合（累计匹配数 / 累计总数）。

## 五、检测指标分析与已知局限

检测 F1 偏低（medium 全量 36.84%）。通过两个排除实验定位原因：

1. **排除检测阈值**：框阈值从默认降至 0.4，召回率仅 +1.7%（20 张子集），阈值非主因。
2. **排除标注粒度**（行级口径对照，2026-09-28）：把词级 GT 按 y 中心聚类合并成行级框后重算（30 张子集）：

| 口径（medium，30 张，IoU 0.5） | 精确率 | 召回率 | F1 |
| --- | --- | --- | --- |
| 词级（原始标注） | 64.8% | 28.2% | 39.3% |
| 行级（合并后） | 41.4% | 32.4% | 36.3% |

行级召回仅比词级高 4 个点，F1 与词级同量级。若粒度错配是主因，行级口径下应大幅回升，实际未发生。

**IoU 敏感性分析**（同 30 张，medium）：

| IoU | 词级 P / R / F1 | 行级 P / R / F1 |
| --- | --- | --- |
| 0.3 | 88.3% / 38.3% / 53.5% | 56.2% / 44.0% / 49.3% |
| 0.5 | 64.8% / 28.2% / 39.3% | 41.4% / 32.4% / 36.3% |
| 0.7 | 43.2% / 18.8% / 26.2% | 20.4% / 15.9% / 17.9% |

最宽松阈值（0.3）下行级召回也仅 44.0%——约 56% 的文字行附近没有任何检测框（**漏检实锤**）；同一阈值下词级精确率 88.3% 远高于行级 56.2%——预测框与词级几何贴合、与整行错位（**粒度因素实锤**）。

**最终结论（两因素，漏检为主）**：

1. **难例漏检（主因）**：约 56% 文字行在 IoU 0.3 下仍无匹配，PP-OCR 对 ICDAR2015 的小字、倾斜、低对比、弯曲文字检不出来。
2. **输出粒度介于词与行之间（次因）**：预测框与词级 GT 高度贴合（0.3 下 P 88.3%）、与行级 GT 明显错位（0.3 下 P 56.2%），在词/行两种口径下均被部分惩罚。

阈值调整（召回仅 +1.7%）、粒度口径调整（行级召回仅 +4 点）均无法单方面解释；本镜像的检测标注文字被剥离为统一 `###` 占位符，无法区分有效文本区与「无效区」（do-not-care），全部按有效 GT 计入，对指标口径亦有影响。论文按排除法 + 敏感性分析呈现。

## 六、轻量模型对比（medium vs small，2026-09-26）

为提升界面响应速度，系统默认部署 PP-OCRv6 **small** 模型（检测 + 识别），评估仍以 medium 为准。对比数据：

| 指标 | medium | small |
| --- | --- | --- |
| 识别字符准确率（2074 张，忽略大小写） | 82.89% | 75.86% |
| 识别行级准确率（同全量） | 71.50% | 63.69% |
| 检测 F1（500 张，IoU 0.5） | 36.84% | 32.70% |
| 检测精确率 / 召回率（同全量） | 61.86% / 26.23% | 60.47% / 22.41% |
| 整图耗时（test.jpg，39 行，CPU） | 115.6s | **21.7s** |
| 识别平均耗时 / 单行图 | 1.757s | 0.162s |
| 检测平均耗时 / 整图 | 27.13s | 3.86s |

结论：small 以识别字符准确率约 **-7 点**、检测 F1 **-4 点**为代价，换得整图识别约 **5.3 倍**提速（检测约 7 倍、识别约 10.8 倍）。识别精度代价高于 100 张抽样时的预估（抽样低估了小模型差距），论文引用以全量数字为准。检测 F1 的下降主要来自召回（检出框减少），叠加在词级/行级粒度错配的结构性偏低之上。

## 七、预处理消融实验（2026-09-26）

在 ICDAR2015 recognition/test 的 200 张单行图上，对比 5 种预处理配置（模型 PP-OCRv6 small，忽略大小写）：

| 配置 | 字符准确率 | 行级准确率 | 平均耗时/张 |
| --- | --- | --- | --- |
| 无预处理 | **73.51%** | **61.50%** | 0.140s |
| 仅去噪 | 72.42% | 58.50% | 0.132s |
| 仅CLAHE | 60.01% | 47.50% | 0.125s |
| 仅锐化 | 67.31% | 56.00% | 0.130s |
| 全开（默认） | 53.65% | 42.00% | 0.118s |

结论：**对清晰图像，预处理是负优化**。全开比无预处理字符准确率低约 20 个百分点，其中 CLAHE 伤害最大（-13.5），锐化次之（-6.2），去噪轻微有害（-1.1）。原因：该子集图像本身清晰、对比度高，对比度增强与锐化放大了噪声与压缩伪影。

系统含义：预处理开关默认应处于**关闭**状态，仅在低光照 / 模糊 / 低对比度图像上按需启用。该结论亦与阶段 1 在整图扫描件上的观察一致（预处理无增益）。

**退化图补测**（同 200 张图，合成退化：高斯模糊 5×5 σ=1.2 + 对比度×0.7 -15 + 高斯噪声 σ=15，种子 42）：

| 配置 | 字符准确率 | 行级准确率 |
| --- | --- | --- |
| 仅去噪 | **33.16%** | **28.00%** |
| 无预处理 | 17.51% | 16.00% |
| 仅CLAHE | 17.11% | 14.00% |
| 全开（默认） | 14.69% | 12.50% |

结论：退化图上**仅去噪**是唯一有效项（较无预处理 +15.7 字符点，噪声是中值滤波的对症场景）；CLAHE 无益、锐化有害；「全开」组合在清晰图与退化图上均非最优。

**其余场景补测**（同 200 张图、同模型，每组对比「无预处理 vs 对应算子」）：

| 算子 | 场景 | 无预处理 | 算子开启 | 差值 |
| --- | --- | --- | --- | --- |
| 小字放大 | 缩小 2 倍 | 32.07% | 76.43% | **+44.4** |
| 锐化 | 重模糊图（9×9 σ=2.5） | 25.58% | 29.32% | **+3.7** |
| CLAHE | 低对比图（×0.45 -30） | 68.04% | 68.13% | +0.1 中性 |
| 倾斜校正 | ±12° 倾斜图 | 71.40% | 24.81% | **-46.6 有害** |

**消融总结论**：

1. 各算子有明确适用域：小字放大收益最强（+44.4），去噪次之（+15.7），锐化温和有效（+3.7）；CLAHE 实测中性；倾斜校正在 ±12° 范围内有害——识别模型自身具备倾斜容差（71.40% 仅比清晰图基线低约 2 点），且本实现的 minAreaRect 角度估计对真实文字存在偏差（深色背景 Otsu 反相问题已修复，残余偏差源于字符分布拟合）。
2. 预处理不应默认开启；按图像问题选择对症算子。系统 UI 因此只暴露三个实测正收益算子（小字放大 / 去噪 / 锐化），默认全不勾，CLAHE 与倾斜校正保留在模块中但不进 UI。
