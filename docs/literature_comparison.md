## 一、为什么需要这张表

论文标题与摘要都写了「ICDAR2015 对比实验」，但仓库里**没有任何文献对照**。结果是本项目的
检测数字（legacy 36.43% / deteval 42.21%）**没有任何参照系**——读的人无法判断它算好还是差。
一张带"是否微调"列的文献表能把这件事说清楚，也是答辩时最容易被追问的地方。

## 二、⚠️ 我为什么没有替你填数字

我尝试用检索与抓取来核对，但**失败了，而且失败的原因本身很重要**：

**同一方法在不同来源里的数字互相矛盾。** 我实际看到的：

| 方法 | 来源 A | 来源 B |
| --- | --- | --- |
| CTPN | 60.4 / 53.8 / 56.9 | **74.0 / 52.x / …** |
| EAST | — | 83.57 / 73.47 / **78.20** |

原因不是谁抄错了，而是**同一个方法名下的配置本来就不唯一**：

- backbone 不同（VGG16 / ResNet50 / ResNet50-DCN）；
- 是否**多尺度**测试；
- 是否用了**额外训练数据**（如 SynthText 预训练）；
- 各论文用的**评测脚本版本**不同（官方 deteval 有多个修订版，忽略规则与匹配方式有差异）。

因此，"DBNet 的 F1 是多少"这个问题**没有唯一答案**。凭记忆或从二手转述填数字，等于在论文里
制造新的"无存档数字"——正是这次审计反复批评的问题。**所以我停手了，改为给出模板 + 核对清单。**

（另外：可检索到的结果多为 PDF 表格，抓取工具无法可靠提取；GitHub 与 MMOCR 文档页也抓取失败。）

- **backbone / 是否多尺度 / 训练数据**：不写这三项，两个数字根本不可比；
- **是否在 IC15 微调**：这是本项目与绝大多数文献**最本质的区别**——本项目是**零样本**

- **匹配/评测方案**：官方 deteval 允许**一对多**匹配，本项目是 **IoU≥0.5 贪心一对一**
  （见 `docs/evaluation_report.md` §四）。方案不同，数字不可逐字对比。
